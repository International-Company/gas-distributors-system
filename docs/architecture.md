# البنية والقرارات التقنية

## نظرة عامة

```
src/
  app/                 صفحات Next.js وواجهات API
    (app)/admin/...    صفحات مديري النظام
    (app)/d            صفحات الموزّع
    (app)/account      حسابي (كلمة المرور، PIN، الأجهزة)
    api/v1/...         واجهات JSON (موثقة في docs/api.md)
  server/              منطق الخادم فقط (لا يُستورد في المتصفح)
    db.ts              الاتصال وسياقات العزل withTenant / withSystem
    actor.ts           هوية المنفذ والتحقق من الصلاحيات
    permissions.ts     صلاحيات مديري النظام
    audit.ts           كتابة سجل التدقيق
    auth/              كلمات المرور، الجلسات، PIN
    services/          خدمات الأعمال (الموزّعون، المديرون، الإعدادات، السجلات، التصدير)
    http/              حراس الصفحات وAPI، معالجة الأخطاء، CSRF
  components/          مكونات الواجهة
  lib/                 أدوات مشتركة (تنسيق التواريخ، القائمة)
prisma/
  schema.prisma        مخطط البيانات
  migrations/          ترحيلات SQL (منها ترحيل الحماية: RLS والـ triggers)
scripts/               سكربتات التشغيل والإعداد
tests/                 اختبارات الوحدات والتكامل
```

**القاعدة:** كل عملية تمر عبر خدمة في `src/server/services`، تستقبل `Actor` الذي بناه الخادم من الجلسة، وتتحقق من الصلاحية بنفسها. واجهات API والصفحات طبقة رقيقة فوق الخدمات. لا تُبنى الهوية أبدًا من بيانات يرسلها العميل.

## عزل بيانات الموزّعين (طبقتان)

1. **طبقة التطبيق:** خدمات الموزّع تستخدم `withTenant(actor.distributorId, ...)`، وخدمات الإدارة تتحقق من دور المدير وصلاحيته قبل استخدام `withSystem`.
2. **طبقة قاعدة البيانات (Row-Level Security):**
   - التطبيق يتصل بالدور `gas_app` (ليس مالك الجداول ولا يملك `BYPASSRLS`)، فتُطبق عليه سياسات RLS دائمًا.
   - كل معاملة تحدد سياقها بـ `set_config(..., true)` (محلي للمعاملة فقط):
     - `app.distributor_id`: سياق موزّع واحد.
     - `app.bypass_rls = on`: السياق المركزي (المديرون، المصادقة).
   - **فشل مغلق:** أي استعلام خارج السياقين لا يرى أي صف من الجداول المعزولة.
   - الجداول المعزولة حاليًا: `distributors` و `users` و `audit_logs`. كل جدول بيانات تشغيلية في المراحل القادمة (كشوف، مواطنون، دورات، عمليات، مخزون، مالية) سيحمل `distributorId` وسياسة RLS نفسها.

اختبارات `tests/integration/isolation.test.ts` تتحقق من ذلك على قاعدة PostgreSQL حقيقية.

## المصادقة والجلسات

- كلمات المرور وPIN مجزأة بـ **Argon2id** (معاملات OWASP: 19 MiB، تكراران).
- الجلسة رمز عشوائي (256 بت) في ملف تعريف ارتباط `HttpOnly` و `SameSite=Lax` و `Secure` في الإنتاج. قاعدة البيانات تخزن **تجزئة SHA-256** للرمز فقط.
- يُتحقق من كل طلب على الخادم: الإبطال، مهلة عدم النشاط (من الإعدادات)، العمر الأقصى (7 أيام)، حالة المستخدم، حالة الموزّع وصلاحيته.
- **قفل الحساب** بعد عدد المحاولات الفاشلة المحدد في الإعدادات، مع حد إضافي للمحاولات الفاشلة من عنوان IP واحد (50 خلال 15 دقيقة).
- رسالة الفشل موحدة لكلمة مرور خاطئة ولمستخدم غير موجود، مع تحقق وهمي بزمن مماثل حتى لا يُكشف وجود الحساب.
- كل محاولة دخول (ناجحة أو فاشلة) تُسجل مع الوقت وعنوان IP في `login_attempts` (للإضافة فقط).
- **PIN:** مرتبط بجهاز واحد عبر رمز جهاز في ملف تعريف ارتباط `HttpOnly` و `SameSite=Strict`. تفعيله يتطلب كلمة المرور، ويُلغى بعد 5 محاولات خاطئة. جلسة PIN **لا تكفي للعمليات الحساسة**.
- **العمليات الحساسة** (إعادة تعيين كلمات المرور، إدارة المديرين، الخروج من كل الأجهزة) تتطلب تحققًا بكلمة المرور خلال آخر 15 دقيقة. الواجهة تطلبه تلقائيًا ثم تعيد المحاولة.
- **نسيان كلمة المرور:** يعيد المدير تعيينها بعد التحقق من الهوية، مع إلزام بتسجيل السبب وطريقة التحقق، وإلزام الموزّع بتغييرها عند الدخول، وإبطال الجلسات وPIN افتراضيًا.
- **CSRF:** كل طلب معدِّل يجب أن يحمل `Origin` مطابقًا للمضيف، إضافة إلى `SameSite`.

## دورة حياة حساب الموزّع

| الحالة | الدخول | ملاحظات |
|---|---|---|
| نشط `ACTIVE` | مسموح | قد يكون تجريبيًا أو فعليًا، بتاريخ انتهاء أو بلا مدة |
| معلّق `SUSPENDED/MANUAL` | ممنوع | قرار إداري مع سبب |
| منتهي `SUSPENDED/EXPIRED` | ممنوع | تعليق تلقائي عند انتهاء الصلاحية |
| مؤرشف `ARCHIVED` | ممنوع | مخفي من القائمة الافتراضية؛ لا تُحذف أي بيانات |

**التعليق التلقائي:** يُنفذ عند كل تحقق من جلسة، وعند كل محاولة دخول، وعند عرض قوائم الإدارة. لا يمكن لحساب منتهٍ تنفيذ أي عملية حتى دون مهمة مجدولة. التحديث شرطي (`WHERE status = 'ACTIVE'`) فلا يتكرر السجل عند تزامن طلبين.

التعليق والأرشفة يبطلان كل جلسات الموزّع فورًا.

## سجل التدقيق

- يُكتب **داخل المعاملة نفسها** مع العملية، فلا تُعتمد عملية دون سجلها.
- يحفظ القيم القبلية والبعدية والسبب والمنفذ وعنوان IP. يحذف تلقائيًا أي حقل سري (`passwordHash` و `pinHash` وغيرهما).
- **محمي من التعديل** على مستويين:
  - `gas_app` لا يملك صلاحيات `UPDATE` و `DELETE` و `TRUNCATE` على الجدول.
  - Triggers تمنع التعديل والحذف والتفريغ حتى لمالك قاعدة البيانات.
- المبدأ نفسه مطبق على `login_attempts` و `error_logs`.

## الأخطاء التقنية

كل خطأ غير متوقع في API يُسجل في `error_logs` (الرسالة، المسار، المستخدم)، ويرجع للعميل رسالة عامة دون تفاصيل داخلية. الإشعار الداخلي لمدير النظام عند الأخطاء المهمة يُضاف مع نظام الإشعارات (المرحلة 7).

## القرارات التقنية والافتراضات

| القرار | السبب |
|---|---|
| Prisma مع ترحيلات `migrate` (لا `db push`) | تاريخ تغييرات قابل للمراجعة، ولا حذف بيانات صامت في الإنتاج |
| RLS في PostgreSQL مع دور تطبيق منفصل | عزل لا يعتمد على تذكّر كل مطور إضافة شرط الموزّع |
| جلسات في قاعدة البيانات بدل JWT | إمكانية الإبطال الفوري (تعليق، خروج من كل الأجهزة، مهلة عدم النشاط) |
| واجهات `/api/v1` بدل Server Actions | API موثقة قابلة للتوسع، وأساس للمزامنة دون اتصال (المرحلة 6) |
| التواريخ بتوقيت `Asia/Gaza` وبصيغة يوم/شهر/سنة بأرقام لاتينية | وضوح التواريخ داخل نص عربي |
| إعدادات العملة لا تغيّر العمليات السابقة | كل عملية مالية (المرحلة 4) ستخزن عملتها وقيمتها وقت التنفيذ |
| إعادة الحساب من الأرشيف تعيده «معلّقًا» | التفعيل قرار منفصل بصلاحية محددة |
| إدارة المديرين للمدير الرئيسي فقط، مع بقاء مدير رئيسي نشط واحد على الأقل | منع تصعيد الصلاحيات وفقدان الإدارة |

## المرحلة 2: الكشوف والمواطنون والدورات

### دورة حياة الكشف

```
رفع الملف ─► حفظ الملف الأصلي ─► استخراج جدول خام ─► ربط الأعمدة ─► صفوف + تحقق
                                                                          │
                     (قيد المراجعة: تصحيح، استبعاد، تغيير الربط، تحديد الدورة)
                                                                          │
                                        اعتماد صريح ──► مواطنون + استحقاقات
                                        أو إلغاء (يبقى محفوظًا)
```

- **الاستخراج:** Excel (‎.xlsx) عبر ExcelJS؛ PDF نصي عبر pdf.js (مكتبة unpdf) مع تجميع الكلمات في صفوف وأعمدة حسب مواضعها؛ PDF ممسوح ضوئيًا يُقرأ **في متصفح الموزّع** (pdf.js + tesseract.js) وتُرسل الكلمات ومواضعها فقط إلى الخادم.
- **ربط الأعمدة:** يُكتشف تلقائيًا من كلمات العناوين (أو من المحتوى عند غيابها)، ويمكن للموزّع تعديله في شاشة المراجعة. الجدول الخام محفوظ، فإعادة الربط لا تحتاج إعادة رفع.
- **التحقق:** رقم الهوية (9 أرقام ورقم تحقق Luhn)، الاسم، رقم المواطن، عدد الجرار، التكرار داخل الكشف، استحقاق قائم للمواطن في كشف آخر بالدورة، رقم مواطن مستخدم، اختلاف الاسم عن المسجل، اختلاف المبلغ عن (العدد × السعر). الأخطاء تمنع الاعتماد؛ التنبيهات لا تمنعه.
- **صفوف القراءة الضوئية** تُعلَّم كلها «تحتاج مراجعة». رقم التحقق في الهوية يكشف معظم أخطاء القراءة تلقائيًا.
- **الاعتماد:** في معاملة واحدة مع قفل الكشف والدورة (`SELECT … FOR UPDATE`)، فلا يتكرر حتى مع طلبات متزامنة.
- **الإصدارات:** الكشف الجديد يمكن أن «يحل محل» كشف معتمد. قبل الاعتماد تُعرض الفروق (جدد، تغيّرت بياناتهم، اختفوا). عند الاعتماد: يصبح السابق «إصدار سابق» ويبقى بصفوفه وملفه؛ تُسجل كل تغييرات الاستحقاق في `entitlement_changes`؛ المختفون يُعلَّم استحقاقهم «أُزيل» ولا يُحذف.

### المواطنون والاستحقاقات

- **المواطن لا يُنشأ إلا من كشف معتمد.** لا توجد أي واجهة لإنشاء مواطن أو استحقاق يدويًا؛ المواطن غير الموجود يُسجل «حالة مراجعة» فقط.
- **بيانات الهيئة منفصلة:** الاستحقاق يحفظ ما ورد في الكشف المعتمد (الاسم، الهاتف، رقم المواطن، الكمية، المبلغ ومصدره، السعر والعملة وقت الاعتماد). عمليات الموزّع (المراحل 3 و4) في جداول مستقلة.
- **المبلغ المطلوب (قرار مؤقت):** مبلغ الكشف إن ورد، وإلا عدد الجرار × سعر الدورة. يُحفظ مصدره، ويُنبَّه عند اختلاف الاثنين.
- **رقم المواطن** هو معرّف الجرة التشغيلي **داخل الدورة**: فريد بين الاستحقاقات القائمة في الدورة نفسها (قيد في قاعدة البيانات)، وقد يتكرر بين الدورات.
- **الدمج:** اقتراحات بأسماء متشابهة (≥ 85٪) وأرقام هوية مختلفة؛ قرار بشري فقط؛ يُرفض إن كان للسجلين استحقاق قائم في الدورة نفسها؛ لا تُجمع الكميات؛ السجل الثانوي يبقى مربوطًا بالأساسي، والبحث برقمه يوصل للأساسي.
- **تشابه الأسماء يُحسب في الكود** لا بـ pg_trgm، لأن الأخير يتجاهل الحروف العربية في بعض إعدادات لغة قاعدة البيانات.

### الحماية في قاعدة البيانات (ترحيلات phase2)

| الحماية | كيف |
|---|---|
| عزل كل جداول المرحلة | سياسة RLS على 11 جدولًا |
| منع ربط سجل موزّع بسجل موزّع آخر | مفاتيح خارجية مركّبة `(id, distributorId)`، لأن فحص المفاتيح لا يخضع لـ RLS |
| دورة نشطة واحدة | فهرس فريد جزئي `WHERE status = 'OPEN'` |
| استحقاق قائم واحد لكل مواطن في الدورة | فهرس فريد جزئي |
| رقم مواطن فريد في الدورة | فهرس فريد جزئي |
| لا حذف للبيانات من التطبيق | سحب صلاحية `DELETE` من دور التطبيق على كل الجداول، عدا التصنيفات وصفوف كشف قيد المراجعة |
| صفوف الكشف المعتمد ثابتة | trigger يمنع أي تعديل أو حذف لصفوف كشف ليس قيد المراجعة |
| سجلات ثابتة | `cycle_events` و `entitlement_changes` و `file_blobs` للإضافة فقط |

### تخزين الملفات (مؤقت)

الملفات الأصلية تُحفظ في PostgreSQL (`file_blobs`) خلف واجهة `storeFile/readOwnFile`، إلى حين اعتماد مزوّد تخزين سحابي. الميزة الحالية: الملفات مشمولة في نسخ قاعدة البيانات الاحتياطية. القيد: حجم القاعدة يكبر مع الملفات (الحد 20 ميغابايت للملف). صور الهويات **لا تُرفع ولا تُخزن إطلاقًا**؛ تُقرأ على الجهاز.

## المرحلة 3: الجرار والمخزون والشحنات

### نموذج الجرة

```
(استحقاق بعدد n) ─ استلام فارغة ─► جرة EMPTY ─ تعبئة (داخلية أو ضمن شحنة) ─► FILLED ─ تسليم ─► DELIVERED
                                       │                                         │                  │
                                       └──────────── إلغاء آخر عملية يعيد الحالة السابقة (VOID ◄ EMPTY ◄ FILLED)
```

- **كل جرة سجل مستقل.** رقمها رقم المواطن في الكشف («501»)، ومع تعدد الجرار «501-1» و«501-2». الرقم فريد داخل الدورة بين الجرار غير الملغاة.
- **العملية** (استلام، تعبئة، تسليم) سجل في `cylinder_operations`. القيد الجزئي `(cylinderId, type) WHERE status = 'ACTIVE'` يجعل قاعدة البيانات نفسها تمنع تعبئة الجرة مرتين أو تسليمها مرتين.
- **منع التكرار عند إعادة الإرسال:** معرّف عملية من الجهاز فريد لكل موزّع. يُفحص قبل التنفيذ ثم **بعد الحصول على قفل الصف**. الطلب المكرر المتزامن ينتظر القفل، ثم يرجع نتيجة الأول بدل أن يرجع خطأ.
- **الهوية:** رقم البطاقة المدخل يجب أن يطابق صاحب الاستحقاق، ولا يوجد أي مسار تجاوز. عدم المطابقة يوقف العملية ويسجل حالة مراجعة في معاملة مستقلة.
- **الدورة المغلقة:** لا يُستلم فيها فارغ جديد، لكن الجرار المعلقة تُعبأ وتُسلّم لأصحابها.
- **الاستحقاق المُزال بإصدار جديد:** جراره المستلمة تبقى قابلة للتعبئة والتسليم، ولا يُستلم له جديد. الإصدار الذي يغيّر رقم مواطن له جرار مستلمة، أو يُنقص العدد تحته، يُرفض في المراجعة.
- **العمليات لا تمس المال:** لا عملية جرار تغيّر مبلغًا. الدفع عملية مالية منفصلة (المرحلة 4).

### المخزون

| الحركة | فارغ | معبأ (جرار مواطنين) | إضافي (من الشحنات) |
|---|---|---|---|
| استلام فارغة | +1 | | |
| تعبئة (داخلية أو ضمن شحنة) | −1 | +1 | |
| تسليم | | −1 | |
| شحنة: الكمية غير المرتبطة بمواطنين | | | +n |
| إلغاء | عكس الحركة الأصلية مرة واحدة (`reversesId` فريد) | | |

- **الشحنة لا تضاعف المخزون:** الجزء المرتبط بمواطنين يُسجل **تعبئةً** لجرار مستلمة فارغة (حركة FILL لكل جرة، مع مرجع الشحنة)، والباقي حركة `SHIPMENT_EXTRA` مستقلة. الجرة الواحدة لا تُعبأ إلا مرة.
- **الرصيد** في `inventory_balances` يُحدَّث ذريًا مع كل حركة (`UPDATE … RETURNING` يقفل الصف). قيد في قاعدة البيانات يمنع أي رصيد سالب، فالحركة غير المنطقية تُرفض. كل حركة تحفظ الرصيد بعدها.
- **المطابقة:** الرصيد يُقارن دائمًا بحالات الجرار الفعلية وبالكميات الإضافية للشحنات النافذة. أي اختلاف يظهر تنبيهًا ولا يُصحح تلقائيًا.

## المرحلة 4: المالية

### الفصل بين المجالات

| المجال | السجل | يؤثر في |
|---|---|---|
| تحصيلات المواطنين | `payments` (مرتبطة باستحقاق دورة) | متبقي المواطن، ومقبوضات الصندوق |
| المصروفات | `expenses` | مدفوعات الصندوق |
| حسابات المحطات | `shipments` (القيمة = العدد × سعر الشراء) و `station_payments` | رصيد المحطة؛ ودفعاتها مدفوعات من الصندوق |
| الجرار والمخزون | المرحلة 3 | لا تمس أي مبلغ |

- **سعران مختلفان:** سعر البيع للمواطن تحدده الهيئة (سعر الدورة، محفوظ في كل استحقاق). سعر الشراء من المحطة يُقترح من سعر المحطة الافتراضي ويُحفظ **في كل شحنة**، فتغيير أي منهما لاحقًا لا يغيّر الحسابات السابقة.
- **العملة:** كل سجل مالي يحفظ عملته وقت إنشائه. التحصيل يأخذ عملة الاستحقاق، والمصروفات ودفعات المحطات تأخذ عملة الإعدادات وقتها.
- **الصندوق** يحسب: المقبوضات − المصروفات − دفعات المحطات. لا فتح ولا إغلاق يومي. **الرصيد محسوب ولا يثبت النقد الفعلي.** التصفية بالدورة تعني: التحصيلات المرتبطة بالدورة، والمصروفات ودفعات المحطات خلال فترتها (من الفتح إلى الإغلاق أو الآن).
- **الاستحقاق القابل للتحصيل:** القائم في الكشف، أو المُزال الذي استُلمت له جرار.

### الحماية في قاعدة البيانات

| الحماية | كيف |
|---|---|
| لا دفع زائد | trigger قبل الإدراج يقفل صف الاستحقاق ويرفض أي دفعة تجعل المدفوع أكبر من المطلوب، إضافة إلى الفحص في الكود |
| لا خفض للمطلوب تحت المدفوع | trigger على `entitlements.amountDue` يحمي من تعديل يدوي أو إصدار كشف جديد |
| السجلات لا تُعدّل ولا تُحذف | trigger `app_cancel_only` على التحصيلات والمصروفات ودفعات المحطات والشحنات وعمليات الجرار: التغيير الوحيد المسموح ACTIVE ← CANCELLED مع حقول الإلغاء، مرة واحدة |
| مبالغ موجبة | قيود CHECK |
| العزل | RLS ومفاتيح مركّبة كبقية الجداول |

## المرحلة 5: التقارير والتصدير والإعدادات

- **محرك تقارير واحد** (`src/server/reports`): كل تقرير تعريف (عنوان، فلاتر، أعمدة بأنواعها، دالة استعلام). النتيجة نفسها تُعرض في الشاشة، وتُصدّر إلى Excel، وتُطبع.
- **العزل:** تقارير الموزّع تُنفذ داخل `withTenant`، فـ RLS يقصر حتى SQL الخام على بياناته. المدير يحتاج `reports.view` ويختار موزّعًا واحدًا، فيُنفذ التقرير في سياق ذلك الموزّع فقط. معرّف دورة لموزّع آخر يرجع «غير موجود».
- **التقرير المركزي** يعرض كل موزّع بأرقامه دون ترتيب أو مقارنة أداء، كما تنص المواصفات.
- **حدود الفترات** تُحسب بتوقيت غزة ثم تُحوّل إلى UTC داخل SQL، فلا يتأثر التقرير بتوقيت الخادم.
- **Excel:** من اليمين لليسار، برأس يذكر الموزّع والفلاتر ووقت الإنشاء، وأعمدة المال بتنسيق رقمي، وصف إجماليات.
- **PDF عبر الطباعة (قرار):** صفحة طباعة عربية بألوان ثابتة، رأس جدول يتكرر في كل صفحة، و«حفظ PDF» من نافذة طباعة المتصفح. السبب: تشكيل الحروف العربية في المتصفح مضمون، ولا يحتاج الخادم متصفحًا كاملًا (ذاكرة وتكلفة أعلى على Railway). يمكن إضافة توليد PDF من الخادم لاحقًا إن لزم.
- **كل تصدير وطباعة يُسجل في التدقيق:** من، وأي تقرير، وأي فلاتر، وعدد الصفوف.
- **حد أقصى 20,000 صف للتقرير**، مع تنبيه عند بلوغه. الشاشة تعرض أول 300 صف، والتصدير والطباعة يشملان الكل.
- **الإعدادات:**
  - **الشعار:** مخزّن في الإعدادات. يُتحقق من نوعه من محتواه (PNG وJPEG وWebP فقط، دون SVG)، ولا يُحمّل مع كل تحقق من الجلسة.
  - **الملفات:** أنواع الملفات المسموحة والحد الأقصى للحجم يطبقان على رفع الكشوف الآن، وعلى المرفقات لاحقًا.
  - **القائمة الجانبية:** أسماء الأقسام وترتيبها وإخفاؤها. الإخفاء تنظيمي فقط، ولا يمكن إخفاء الأقسام الأساسية.

## كشوف الهيئة الفعلية

اختُبر الاستيراد على كشف حقيقي من «نظام توزيع الغاز» (1018 مواطنًا) محليًا دون رفعه إلى المستودع، فخرج دون أي خطأ، وكل أرقام الهوية اجتازت رقم التحقق. خصائص الصيغة:

- لا يوجد عمود «رقم المواطن»؛ عمود **«المتسلسل»** هو رقم المواطن.
- الأسماء الطويلة **تلتف على سطرين** في PDF، فتُدمج بخوارزمية «سطر المفتاح»: السطر الذي لا يحمل رقم هوية يُلحق بأقرب سطر يحمله.
- قد يرد **رقم هوية آخر بين قوسين** بعد الاسم؛ يُفصل ويُنبَّه إليه.
- **نص PDF يفقد بعض الحروف** (الياء والألف المقصورة الأخيرة وأحيانًا الكاف واللام المضعفة) لأن الخط المضمّن لا يعرّفها. الأرقام سليمة. لا نصحح الأسماء تخمينًا، ونعرض تنبيهًا.
- الرأس يحوي **تاريخ الكشف ورقم الميزان**، ويُستخدمان عنوانًا مقترحًا.
- أعمدة الأوزان (فارغ، ممتلئ، الغاز) فارغة في الكشف ولا تُستورد. الأوزان تُسجل عند العمليات (انظر أدناه).

## رقم الميزان والأوزان (قرار المالك بعد المرحلة 5)

**الدورة تضم أكثر من كشف**، ولكل كشف «رقم ميزان»، وتسلسله يبدأ من 1. لذلك:

- **رقم المواطن = «الميزان-المتسلسل»** (مثل `295-17`)، ورقم الجرة يتبعه (`295-17`، أو `295-17-1` و`295-17-2` عند تعدد الجرار). هكذا يبقى الرقم فريدًا في الدورة.
- **مصدر رقم الميزان:**
  - يُقرأ من رأس الكشف («رقم الميزان المتسلسل : 295»). البحث عن عبارة «رقم الميزان» تحديدًا، لأن كلمة «ميزان» قد ترد في اسم مواطن يليه رقم هويته.
  - إن لم يوجد في الرأس، يُدخله الموزّع يدويًا في شاشة المراجعة. تغييره يعيد بناء أرقام الصفوف، ثم يعيد التحقق من التعارض.
- **قواعد التطبيق:**
  - يُضاف الميزان فقط إلى المتسلسل العددي.
  - تصحيح صف برقم عددي يُسبق بالميزان تلقائيًا.
- **تحديث كشف معتمد** يرث رقم ميزان الإصدار السابق، ولا يمكن تغييره. السبب: الأرقام مكتوبة فعلًا على الجرار المستلمة.
- **التوافق مع ما سبق:** الكشوف المعتمدة قبل هذا التغيير (بلا رقم ميزان) تبقى أرقامها كما هي.

**الأوزان (اختيارية):**

| متى يُسجل | ما يُسجل | التحقق |
|---|---|---|
| عند استلام الجرة | وزنها فارغة | — |
| عند تسليمها | وزنها ممتلئة | يجب أن يزيد على وزن الفارغة إن سُجل |

- **وزن الغاز** = الممتلئ − الفارغ.
- **أين يظهر:** صفحة الجرة، و«كشف المواطنين» (أعمدة وزن فارغ، وزن ممتلئ، الغاز، كما في كشف الهيئة)، وتصدير Excel والطباعة.
- **التخزين:** الوزن جزء من سجل العملية نفسه (`cylinder_operations.weightKg`). قيد في قاعدة البيانات: أكبر من 0 وأقل من 100 كغ، وفقط على الاستلام والتسليم.
- **التصحيح:** الوزن لا يُعدّل بعد التسجيل، كبقية العملية. يُصحح بإلغاء العملية وتسجيلها من جديد.

## المرحلة 6: التطبيق القابل للتثبيت والعمل دون اتصال

### ما يعمل دون اتصال، ولماذا

| العملية | دون اتصال؟ | السبب |
|---|---|---|
| البحث برقم الهوية في الشباك | نعم | من بيانات الجهاز |
| استلام جرة فارغة | نعم (قابل للتعطيل) | الرقم المعروض على الجهاز يُرسل مع العملية. إن اختلف عن المستحق فعلًا (استلام من جهاز آخر) تُرفض ولا يُعاد الترقيم بصمت |
| تسليم جرة معبأة | نعم (قابل للتعطيل) | الجرة شيء مادي واحد يحمل رقمه، والجهاز يمنع تكرار تسليمها. أي تسليم مزدوج من جهازين يرفضه الخادم ويصبح حالة مراجعة |
| التحصيل | نعم (قابل للتعطيل) | بمبلغ صريح (لا «كامل المتبقي» لأن المتبقي قد يتغير). التحصيل المعلق يُخصم محليًا، والدفع الزائد يرفضه الخادم فيصبح حالة مراجعة |
| الكشوف، والتعبئة والشحنات، والإلغاء، والمصروفات، ودفعات المحطات، والتقارير، والإعدادات | **لا** | تغيّر المخزون والحسابات لعدة مواطنين دفعة واحدة، أو تعتمد على حالة الخادم الكاملة؛ لا يمكن ضمان سلامتها دون اتصال، فهي متوقفة كما تنص المواصفات |

يحدد مدير النظام في الإعدادات:
- أي العمليات الثلاث مسموحة دون اتصال (الافتراضي: الثلاث).
- أقصى عمر لبيانات الجهاز (الافتراضي 24 ساعة، من 1 إلى 72). بعده يُمنع العمل دون اتصال، وتُحذف البيانات من الجهاز.

**السياسة تُفرض على الخادم أيضًا:** عملية من قائمة الانتظار لنوع غير مسموح، أو نُفذت ببيانات أقدم من الحد، تُرفض وتصبح حالة مراجعة.

### التصميم

- **بيانات الجهاز («اللقطة»)** من `GET /api/v1/offline/snapshot`:
  - تشمل المواطنين أصحاب الاستحقاقات القابلة للعمل: الدورة النشطة، وما له جرار لم تُسلّم، وما عليه مبلغ متبقٍ.
  - لكل مواطن: الاسم ورقم الهوية فقط (للمطابقة مع البطاقة)، والجرار، والمطلوب والمدفوع.
  - **لا أرقام هواتف ولا سجل تحصيلات.** كل تنزيل يُسجل في التدقيق.
  - تُحدَّث عند فتح الشباك متصلًا، وكل 5 دقائق، وبعد كل مزامنة.
- **قائمة الانتظار** (IndexedDB):
  - كل عملية تُحفظ على الجهاز **قبل** إرسالها، بمعرّف فريد (`clientOpId`). إغلاق الصفحة أثناء الإرسال لا يضيعها.
  - الحالات:

    | الحالة | المعنى |
    |---|---|
    | محلية | لم تُرسل بعد |
    | بانتظار المزامنة | أُرسلت ولم يصل التأكيد، فتُعاد بالمعرّف نفسه فلا تتكرر |
    | متزامنة | أكدها الخادم |
    | تحتاج مراجعة | رفضها الخادم |

  - **الواجهة لا تقول «تم» إلا بعد تأكيد الخادم.** ما عدا ذلك تقول «حُفظ على الجهاز (بانتظار المزامنة)».
- **منع التكرار على الجهاز:** العمليات غير المتزامنة تُطبق على العرض. الجرة المستلمة محليًا تظهر، والمسلّمة محليًا تُعلَّم «سُلّمت»، والتحصيل المعلق يُخصم من المتبقي. فلا يكرر الجهاز عملية تنتظر المزامنة.
- **منع التكرار بين الأجهزة:** الخادم يعيد كل التحقق بالمسارات العادية نفسها (الهوية، الرقم، الحالة، المتبقي)، مع القيود الفريدة ومعرّفات منع التكرار.
- **التعارضات:** ما يرفضه الخادم من عملية نُفذت دون اتصال يُسجل **حالة مراجعة «تعارض مزامنة»** على الخادم:
  - حالة واحدة لكل عملية مهما أُعيدت المزامنة (`sourceOpId` فريد).
  - تظهر في «حالات المراجعة» لكل أجهزة الموزّع، وفي قائمة الجهاز برسالة الخادم.
  - لا يُحسم أي تعارض تلقائيًا.
- **الوقت:**
  - تُحفظ العملية بوقت تنفيذها على الجهاز (`offlineAt`) إلى جانب وقت وصولها.
  - التحصيل دون اتصال يُؤرَّخ بوقت تنفيذه.
  - يُرفض وقت تنفيذ في المستقبل (ساعة جهاز خاطئة).
- **عملية متصلة انقطع اتصالها قبل التأكيد:** تبقى «بانتظار المزامنة» وتُعاد بالمعرّف نفسه.
  - لا تخضع لسياسة العمل دون اتصال، لأنها لم تُنفذ ببيانات الجهاز.
  - في التسليم، إن كان التسليم دون اتصال غير مسموح، تقول الواجهة صراحةً: لا تسلّم الجرة حتى يتأكد التسليم.
- **الجلسة:** المزامنة تستخدم جلسة المستخدم نفسه. إن انتهت الجلسة أثناء الانقطاع، تتوقف المزامنة وتطلب الدخول. العمليات لا تُحذف، وتُنسب دائمًا لمن نفذها.
- **عامل الخدمة** (`/sw.js`، يحمل رقم البناء):
  - يحفظ صفحتي الشباك والمزامنة وملفات البناء، فتفتحان دون اتصال.
  - طلبات API لا تُحفظ أبدًا.
  - كل نشر جديد يحذف ذاكرة النسخة السابقة.
- **التثبيت:** بيان تطبيق عربي من اليمين لليسار (`/manifest.webmanifest`) مع أيقونات، وزر «تثبيت التطبيق» حين يتيحه المتصفح.

### حماية البيانات على الجهاز (وحدودها بصراحة)

- **التشفير:** اللقطة والقائمة مشفرتان بـ AES-GCM بمفتاح يُولد على الجهاز ولا يمكن تصديره (WebCrypto). نسخ ملفات المتصفح لا يكشف الأسماء وأرقام الهوية نصًا صريحًا، وهذا مختبر.
- **ما يُحذف ومتى:**
  - عند الخروج: اللقطة وذاكرة الصفحات.
  - بعد انتهاء صلاحية اللقطة: اللقطة.
  - عند دخول مستخدم آخر على الجهاز نفسه: اللقطة.
- **العمليات غير المتزامنة لا تُحذف** لأن لها أثرًا فعليًا. الخروج يحذرك منها. ولا يراها مستخدم آخر، بل يُبلَّغ بعددها فقط.
- **حد لا يمكن تجاوزه في المتصفح:** من يملك الجهاز وهو مفتوح على حساب الموزّع يستطيع قراءة ما يعرضه التطبيق. التشفير يحمي البيانات المخزنة، ولا يحمي جهازًا مفتوحًا. الحماية هنا تنظيمية:
  - قفل الهاتف.
  - تقصير صلاحية بيانات الجهاز من الإعدادات.
  - تسجيل الخروج من الأجهزة المشتركة.

## قيود معروفة

- عرض الجلسات النشطة لكل جهاز بالتفصيل غير متوفر؛ يتوفر عددها وإنهاؤها جميعًا.
- تسجيل الخروج أثناء انقطاع الاتصال يحذف بيانات الجهاز، لكنه لا ينهي الجلسة على الخادم حتى انتهاء مهلة الخمول.
- صفحتا الشباك والمزامنة فقط تفتحان دون اتصال؛ غيرهما يعرض صفحة «لا يوجد اتصال».
- الملفات مخزنة في قاعدة البيانات، والقراءة الضوئية في المتصفح (قرار المالك: البدء بالإعداد الحالي).

## تبسيط واجهة الموزّع (قرار المالك، 15/10/2026)

- **الصفحات المدمجة** (الروابط القديمة تُحوَّل تلقائيًا فلا ينكسر رابط):

  | قبل | بعد |
  |---|---|
  | الغلّة + المقبوض + المصاريف | **الفلوس** بتبويبات (`/d/finance?tab=...`) |
  | الجرار + المخزن | **الجرار**: أرصدة المخزن في الأعلى، وهي نفسها فلاتر القائمة. تنبيه الخلل يظهر فقط عند عدم المطابقة |

- **«شغل بدون نت» خارج القائمة:** يُفتح من مؤشر رأس الصفحة (دون اتصال، أو بانتظار الإرسال، أو بدها مراجعة)، ومن تنبيه صفحة التوزيع.
- **التقارير ستة:**
  - كشف الناس للدورة
  - ناس ما استلموا جرارهم
  - ناس عليهم فلوس
  - الفلوس
  - حسابات المحطات
  - حركة الجرار: سجل حركات المخزن مع الاسم والمستخدم والرصيد بعد كل حركة، بدل تقريري «حركة المخزون» و«عمليات الفترة».
- **ربط أعمدة الكشف مخفي** ما دام التعرف التلقائي نجح، مع رابط صغير لتعديله. يظهر مفتوحًا إن تعذر تحديد عمود أساسي.
- **شريط خطوات للكشف:** ارفع ← راجع ← اعتمد.
- **إرشاد في الصفحات الفارغة:** جملة بالخطوة التالية.
- **أسماء حالات يومية:**
  - الكشف: بانتظار الاعتماد، نسخة قديمة.
  - الجرة: بدها تعبية، جاهزة للتسليم.
  - العمليات دون اتصال: على الجهاز، بانتظار الإرسال، وصلت، بدها مراجعة.
- **لم يُحذف أي ضابط أمان أو دقة،** ولم تُمس أي بيانات.

واجهة الموزّع ثلاثة أقسام فقط، والرئيسية تفتح «الكشف» مباشرة:

| القسم | المسار | الوظيفة |
|---|---|---|
| **الكشف** | `/d/sheet` | ناس الكشف المختار، مع بحث وفلاتر (الكل، ما استلم، عليه فلوس، خالص)، وبجانب كل شخص «سلّم» و«دفع» |
| **الكشوفات** | `/d/statements` | رفع ← مراجعة ← اعتماد |
| **الفلوس** | `/d/finance` | الملخص، والمقبوض، والمصاريف |

- **«سلّم» (جدول `handovers`):**
  - تسليم واحد لكل استحقاق، دون مراحل فارغة/معبأة ودون أرقام جرار.
  - يتطلب كتابة رقم الهوية من البطاقة، ويطابقه الخادم.
  - الخطأ يسجل حالة مراجعة.
  - قيود قاعدة البيانات: تسليم نافذ واحد لكل استحقاق، ولا تعديل ولا حذف. التصحيح بـ«تراجع» مع السبب.
  - يُحسب في التقارير والتحصيل وأثر تحديث الكشف كتسليم كل جرار الاستحقاق.
- **الدورة تلقائية:** عند رفع أول كشف دون دورة نشطة، يُطلب سعر الجرة مرة واحدة وتُنشأ الدورة.
- **دفعات المحطة** تُسجَّل مصروفًا عاديًا.
- **بدون نت:** «سلّم» و«دفع» يعملان من بيانات الجهاز بالضوابط نفسها (لقطة الجهاز تحمل الكشف وحالة التسليم). صفحة «الكشف» محفوظة في عامل الخدمة.
- **ما أُخفي** (باقٍ بروابطه وبياناته، دون حذف):
  - التوزيع بالمراحل (استلام الفارغة، والتعبئة، والتسليم بالأرقام)
  - الجرار والنقلات والمحطات
  - الدورات، وحالات المراجعة، والأسماء المكررة، والتقارير، وصفحات الناس
- **من له جرار مسجّلة بطريقة المراحل** يظهر في «الكشف» بحالته للاطلاع، ولا يُسلَّم بـ«سلّم» حتى لا تختلط الطريقتان.

### صفحة الكشوفات المختصرة (15/10/2026)

- **الرفع بخطوة واحدة:** اسحب الملف أو اختره فيُرفع فورًا. سعر الجرة يُطلب مرة واحدة فقط إن لم توجد دورة.
- **العنوان ورقم الميزان** يُقرآن من رأس الكشف.
- **التحديث التلقائي:** كشف بنفس رقم ميزان كشف معتمد في الدورة النشطة يُعتبر **تحديثًا له تلقائيًا**، مع رسالة وعرض الفروق. يمكن التراجع باختيار «كشف مستقل» من «تفاصيل وإعدادات».
- **القراءة الضوئية** تبدأ تلقائيًا للملف الممسوح.
- **صفحة المراجعة:**
  - ملخص الأرقام (الناس، سليم، تنبيه، خطأ) والفروق إن كان تحديثًا.
  - ثم الإجراء الوحيد المطلوب: زر «اعتمد الكشف (N شخص)» إن لم تكن أخطاء، وإلا تُعرض الصفوف الخاطئة فقط لتصحيحها أو استبعادها.
  - الصفوف والتفاصيل والإعدادات (العنوان، الدورة، الإصدار، رقم الميزان، ربط الأعمدة) مطوية.
- **بعد الاعتماد** ينتقل مباشرة إلى «الكشف».
- **الاعتماد ما زال صريحًا:** ضغطة زر يرسل معها الخادم شرط `confirm: true`، ولا يُستخدم كشف قبل اعتماده.

### صفحة الفلوس (15/10/2026)

صفحة واحدة تجيب عن أسئلة الموزّع اليومية بنظرة (`moneyOverview` في `src/server/services/money.ts`):

- **«المفروض يكون معك الآن»:** كل المقبوض ناقص كل المصاريف منذ البداية، مع المعادلة ظاهرة. دفعات المحطات (الطريقة السابقة) تُحسب مصاريف.
- **الفترة:** اليوم (الافتراضي)، آخر 7 أيام، هالشهر، من البداية، تاريخ محدد. حدود الأيام بتوقيت غزة داخل قاعدة البيانات.
- **أرقام الفترة:** انقبض (وعدد الدفعات)، وانصرف (وعدد المصاريف)، والصافي.
- **باقي على الناس:** المتبقي وعدد الأشخاص، وشريط نسبة المقبوض من المطلوب. زر «شوفهم» يفتح «الكشف» مصفّى على «عليه فلوس».
- **الحركات مجمّعة حسب اليوم:** مع مجموع كل يوم، والإلغاء بسبب.
- **«سجّل مصروف»:** نافذة باختيارات سريعة (دفعة للمحطة، أجرة نقل، عمال، صيانة). الرابط القديم `/d/expenses` يفتحها مباشرة.

### شاشة البداية للتطبيق المثبّت (15/10/2026)

- **شاشة النظام:** بيان التطبيق بخلفية الهوية `#1e5aa8`، فيعرض Android عند الفتح الأيقونة والاسم على الأزرق.
- **شاشة البداية داخل التطبيق** (`src/components/app-splash.tsx`) تكمل شاشة النظام بالأزرق نفسه:
  - المحتوى: الشعار (المرفوع من الإعدادات، وإلا الشعار الافتراضي) واسم النظام ومؤشر تحميل.
  - الاختفاء: تتلاشى عند جاهزية الصفحة، بعد ثانية على الأقل، وخمس ثوانٍ كحد أقصى.
- **متى تظهر:** في وضع التطبيق المثبّت فقط (`display-mode: standalone`)، ومرة واحدة في الجلسة. تُرسم في HTML قبل أي سكربت فلا وميض.
- **للاختبار:** `?splash=1` يحاكي التطبيق المثبّت.
- **iOS:** لا يعرض شاشة نظام من البيان (يحتاج صورًا لكل مقاس جهاز)، فتظهر شاشة البداية داخل التطبيق بعد لحظة بيضاء قصيرة.
